# Fox Travel – نظام حجز وإدارة تذاكر الأتوبيسات

مشروع Node.js + SQLite بواجهة عربية RTL. يحتوي على صفحة طلب حجز عامة ولوحة إدارة محمية وREST API وقاعدة بيانات تنشأ تلقائيًا عند أول تشغيل.

## المتطلبات
- Node.js إصدار 22.13 أو أحدث. يستخدم المشروع وحدة `node:sqlite` المدمجة في Node، ولذلك يشغّل بأمر `--experimental-sqlite` ولا يحتاج تثبيت مكتبات خارجية.
- نظام تشغيل يدعم Node.js (Linux أو Windows أو macOS).

## التشغيل على الجهاز
1. فك ضغط مجلد المشروع.
2. افتح الطرفية داخل المجلد.
3. شغّل: `npm start`
4. افتح `http://localhost:3000`.
5. الدخول للإدارة من زر «الإدارة» بكلمة المرور الأولية `8020`.
6. غيّر كلمة المرور فورًا من تبويب «الإعدادات» قبل إدخال بيانات حقيقية أو إتاحة الموقع للناس.

عند أول تشغيل تُنشأ تلقائيًا قاعدة البيانات `data/fox-travel.sqlite` ومفتاح الجلسات `data/session-secret`. لا تحذف هذين الملفين. مجلد `data` هو بيانات الموقع الدائمة.

## إعداد النظام لأول مرة
1. ادخل لوحة الإدارة.
2. أضف شركات النقل من «الشركات».
3. أضف كل اتجاه مستقل من «خطوط السير»؛ فمثلًا قفط ← رمسيس يختلف عن رمسيس ← قفط.
4. أضف الرحلات من «الرحلات والمواعيد»، وحدد الشركة والخط والموعد والسعر وأيام التشغيل وبداية ونهاية التوفر.
5. لن تظهر للعميل أي رحلة أو سعر قبل إضافتها وتفعيلها.

## تغيير كلمة المرور
- من داخل الموقع: الإدارة ← الإعدادات.
- في حالة فقدان كلمة المرور، أوقف الخادم ثم نفّذ: `npm run reset-password -- كلمة_مرور_جديدة_طويلة` ثم أعد تشغيله. اختر كلمة مرور لا تقل عن 10 أحرف. هذا الأمر يلغي الجلسات الحالية.

## النسخ الاحتياطي
- ينشئ الخادم نسخة تلقائية كل 24 ساعة أثناء عمله، ويحتفظ بآخر 14 نسخة في `data/backups`.
- نسخة يدوية: `npm run backup`.
- احتفظ بنسخة خارج الخادم من مجلد `data` بالكامل، وبالأخص قاعدة البيانات ومفتاح `session-secret`. استعادة نسخة قاعدة البيانات تتم بعد إيقاف الخادم واستبدال `data/fox-travel.sqlite` بالنسخة المطلوبة.
- النسخ التلقائي يعمل أثناء تشغيل التطبيق؛ في بيئة الإنتاج يُنصح أيضًا بجدولة نسخة خارجية على مستوى الاستضافة.

## الرفع على استضافة وربط دومين وHTTPS
1. اختر استضافة Node.js تدعم Node 22.13+ وتوفر قرصًا دائمًا (Persistent Disk/Volume). لا تستخدم نظام ملفات مؤقتًا.
2. ارفع ملفات المشروع، واجعل مجلد المشروع أو مجلد `data` على القرص الدائم مع صلاحية كتابة لحساب تشغيل Node.
3. اضبط أمر التشغيل `npm start` ومتغير المنفذ `PORT` حسب الاستضافة.
4. اربط الدومين من لوحة الاستضافة، ثم فعّل شهادة HTTPS/SSL من مزود الاستضافة أو عبر Reverse Proxy موثوق.
5. عند إنهاء HTTPS في Reverse Proxy، مرّر `X-Forwarded-Proto: https` إلى التطبيق حتى يضع Cookie الجلسة بخاصية Secure. لا تعرض منفذ Node مباشرة للعامة إذا كان لديك Proxy.
6. غيّر كلمة مرور الإدارة فور النشر، واحتفظ بنسخ احتياطية خارج حساب الاستضافة.

## نقاط تشغيلية وأمنية
- كلمات مرور الإدارة مخزنة باستخدام `scrypt` مع Salt عشوائي. الجلسات موقعة، وCookie من نوع HttpOnly وSameSite=Strict، وتنتهي بعد 30 دقيقة من عدم النشاط. يوجد CSRF token للعمليات الإدارية، وتحديد لمحاولات الدخول وطلبات الحجز، ورؤوس أمان.
- يتم حساب رسوم الدفع الإلكتروني (+5 جنيه لفودافون كاش وإنستا باي) والإجمالي من بيانات الخادم، وليس من السعر المرسل من المتصفح. السعر المسجل في الطلب نسخة ثابتة لا تتغير عند تعديل الرحلة لاحقًا.
- عند استخدام «أخرى» لا يجري البحث عن رحلة، ويُسجل السعر والموعد باعتبارهما يحددهما الموظف.
- فتح واتساب يبدأ مباشرة من ضغطة الإرسال ثم يُحوّل بعد حفظ الطلب. إذا منع المتصفح النافذة يظهر رابط احتياطي.
- رقم واتساب استقبال طلبات الحجز مضبوط حاليًا على `201098883132`، ورقم واتساب التواصل العام `201289810025`. غيّر الأرقام في `public/index.html` إذا لزم الأمر.
- لا توجد بيانات رحلات تجريبية مزروعة. يجب على الإدارة إدخال البيانات الحقيقية قبل بدء استقبال الطلبات.

## واجهات API الأساسية
- `GET /api/public-data` الشركات والخطوط النشطة.
- `GET /api/trips?origin=...&destination=...&company=...&date=YYYY-MM-DD` المواعيد المتاحة.
- `POST /api/orders` إنشاء طلب حجز.
- `POST /api/login` تسجيل دخول الإدارة.
- `GET /api/admin/bootstrap` بيانات لوحة الإدارة.
- بقية عمليات الإدارة تحت `/api/admin/`.

## تنبيه قبل الاستخدام التجاري
هذا إصدار أساس قابل للتشغيل محليًا ويحتاج اختبار قبول على بيئة الاستضافة الفعلية قبل استقبال أموال أو اعتباره نظام إنتاج نهائيًا. اختبر إعدادات HTTPS والنسخ الاحتياطي، وراجع رقم واتساب المستلم، وأضف بيانات الخطوط والشركات. حماية معدل الطلبات والجلسات في هذا الإصدار داخل ذاكرة عملية Node؛ عند تشغيل أكثر من نسخة خلف موازن أحمال يلزم نقلها إلى مخزن مركزي. كذلك لا يتضمن الإصدار تكامل دفع إلكتروني أو تحققًا من وجود حساب واتساب، ولا يؤكد الحجز تلقائيًا.
